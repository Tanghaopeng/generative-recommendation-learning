# Qwen1.5B 全参数 SFT 与 GRPO 实验方案

日期：2026-10-08。状态：待讨论定稿的实验设计。服务器方案采用单张 RTX A6000 48GB；尚未租用或进行 GPU 训练。配套 JSON 是设计参数，不是已经接通训练入口的运行配置。

## 1. 这次要回答什么

正式数据沿用已处理的 Office Products 2018，先从它的训练集抽取小样本完成工程验证。Industrial 作为单独复现原作者的可选实验，不强制先下载另一套数据。

先回答三件事：Qwen 只学下一商品预测能达到什么水平；文本与 SID 多任务对齐能否改善推荐；在相同 SFT 初始化上，推荐 GRPO 是否带来超过继续 SFT 的收益。之后分别研究码本、商品编码器和协同奖励。

SASRec 与小型 TIGER 已有结果可用，但小型 TIGER 只有 328,320 参数。与 1.5B Qwen 的差异还包含容量与架构，不能把结果差异全部归因于预训练知识。若要严格检验预训练，需要相同 Qwen 架构随机初始化并接受同样训练，这项昂贵对照列为后续可选项。

## 2. 固定输入、SID 与评测

- 用户 86,713，商品 25,898，交互 677,247；数据来源是 `experiments/data_stats.json`。
- 用户内最后一次交互为测试、倒数第二次为验证、此前为训练。该口径是已知目录的用户内留出评测，不是严格全局时间上线模拟。
- 下一商品训练样本调用现有样本规则，核对每轮有效目标数 397,345；历史只取最近 20 件。验证输入为 train，测试输入为 train+valid。
- 首轮固定已有 Adam SID：三层语义码字加第四段碰撞序号。第四段用于区分商品，不视为额外语义层。保持全部 25,898 商品可唯一映射。
- 编码器 MiniLM、RQ-VAE 和 SID 固定，不参与 Qwen 的生成损失反向传播。
- 只用训练行为构造 SFT/RL 目标。目录中公开商品文本可作对齐材料，这是已知商品目录条件；不把留出评论加工成训练标签。
- 最终指标为商品级 HR/Recall@10、NDCG@10、HR/Recall@20、NDCG@20；单目标时 HR=Recall。报告合法率、重复率、历史商品过滤、目录覆盖率和延迟。
- 生成器主比较保持 beam=20；不采 100 个商品负样本。SASRec 是全目录精确评分，生成器是完整目录约束下的有限 beam 近似搜索，这个差异需随结果报告。
- beam=50 的搜索开销/效果作为独立对照；若用于跨生成模型比较，同步重评对应 TIGER，不混用旧 beam20 结果。
- 固定 seed=2026。初步实验单种子，最终主结论在预算允许时补种子；对相同用户的指标差值可做配对 bootstrap，但不能替代训练种子稳定性。

## 3. 实验矩阵与分支来源

| 实验 | 输入权重与训练 | 回答的问题 | 优先级 |
|---|---|---|---|
| B0/B1/B2 | 已有 SASRec、Adam TIGER、EMA TIGER | 当前传统/小型生成基线 | 已完成 |
| Q0 | 原始 Qwen2.5-1.5B-Instruct + 固定新增 SID 词表，不训练 | 初始 logits、合法生成与耗时诊断 | 很小的诊断集 |
| Q1 | 从 Q0 开始，仅做历史 SID→下一 SID 全参数 SFT | 大模型推荐 SFT 基线 | 第一轮 |
| Q2 | 从同一 Q0 独立开始，主任务+文本/SID对齐+历史SID→标题 | 推荐与语言语义对齐的增量 | 第一轮 |
| Q2-C | 从 Q2 的同一个检查点继续 SFT，预算匹配 RL | 区分奖励优化收益和额外训练收益 | GRPO 对照 |
| Q3 | 从 Q2 开始做 GRPO：精确匹配+排名奖励 | MiniOneRec 式优化是否有效 | 第一轮 |
| Q3-B | 同一 Q2、同一 prompt/组大小/步数，仅二元奖励 | 排名奖励的增量 | 第二轮消融 |
| Q3-A | GRPO 中是否保留文本→SID 等对齐任务 | RL 持续对齐的增量 | 第二轮消融 |
| E1 | Q2 固定，替换为已有 EMA SID 后重新训练 | 编码版本的影响 | 第二轮 |
| E2 | 冻结 Qwen3-Embedding-4B→新 RQ-VAE/SID→同配方 Q2 | 商品语义编码器的影响 | 后续 |
| E3 | Q3 加入校准的 SASRec 协同/层级辅助奖励 | 协同信息辅助奖励是否有效 | 后续探索 |

Q0 中新增 SID 的向量尚未学会商品含义，约束解码可以强制产生合法商品，但结果只作诊断，不能作为唯一正式基线。所有 Q1/Q2 分支从同一份新增词表初始化权重出发，保存初始化 SHA256。

多任务 SFT 的任务增加了训练量。第一版保持主任务曝光次数一致并报告辅助样本数、更新步数和输出 token 数；正式归因时补充匹配计算量的 SID-only 对照。Q2-C 同时记录与 Q3 的 GPU 小时及 token 成本，不能把一次 epoch 当作等计算量。

对齐方法参考 [LC-Rec](https://arxiv.org/abs/2311.09049)；SFT 后的推荐奖励优化参考 [MiniOneRec](https://arxiv.org/html/2510.24431v1)。选择少量任务和单卡配置属于我们的简化实验，不宣称原论文完整复现。

## 4. SFT 的具体过程

1. 加载 [Qwen2.5-1.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-1.5B-Instruct) 的预训练权重和 tokenizer，锁定下载 revision。
2. 四段各采用独立命名空间，如 `<sid_0_12><sid_1_43><sid_2_7><sid_3_0>`。计划为四段各添加 256 个原子 token，共 1,024 个，前缀树只允许实际存在的商品路径。
3. 扩展 embedding/输出词表，检查新增 token 每个只占一个 tokenizer ID、旧词 ID 不变，保存同一份初始化供各实验使用。
4. 构造任务文本，首轮保持单卡参考实现的固定 instruction 格式，统一训练、RL与评测 prompt；若改用 Qwen chat template，将它视为单独版本，不能训练与推理混用。
5. 用历史和任务指令作为输入，用下一 SID 或商品标题作为回答。历史、指令与 padding 的 label 为 -100，只对回答和终止 token 计算交叉熵。
6. Teacher forcing：训练时预测目标第二个 token 能看到目标第一个 token；推理时使用模型自身已生成的 token。这是自回归训练/推理的通常差别。
7. 所有 Qwen 参数参与梯度更新，包括新 token 的 embedding 与输出层；不是 LoRA。连续商品向量与 RQ-VAE不更新。
8. 长度超限时按完整商品移除最早历史，避免切断一个 SID；辅助文本另设长度上限。商品名称重复导致文本→SID歧义时，去重或补充属性，记录处理策略和样本数。

样本示例：训练期 A→B→C→D，对主任务输入 SID(A),SID(B),SID(C)，输出 SID(D)。可以从同一训练序列的不同合法位置得到样本，不能从验证/测试位置取下一商品答案。

Q2 第一版建议保留三类任务：下一 SID 预测；商品标题↔SID；历史 SID→下一标题。描述↔SID及用户偏好总结后续再加，避免第一轮依赖额外的大模型标注费用。原单卡实现的 loss mask 见 [数据代码](https://github.com/wbn11/minionerec-single-gpu/blob/bccd7ef70291c5b4b0c30b6222bc491039b4cd18/src/minionerec/data/sft_datasets.py)。

### 建议起步参数（待 A6000 实测）

| 项目 | 我们的起步值 |
|---|---|
| 精度 | BF16 |
| 单次训练 batch | 2，显存允许后到 4 |
| 梯度累积 | 64；batch2时有效batch128 |
| 最大输入+输出长度 | 512；统计截断率，不人为扩大历史 |
| 梯度检查点 | 开启 |
| 学习率 | pilot先5e-5；必要时与1e-4同预算比较 |
| 梯度裁剪 | 1.0 |
| 正式最大轮数 | 首轮先1轮评估，阶段上限暂设3轮 |
| 最佳检查点 | 验证商品级NDCG@10 |

第三方作者用 lr=3e-4、batch4×累积32、最长512，这是原作者的复现参数；我们的较保守起步值不是论文参数。参见 [SFT 实现](https://github.com/wbn11/minionerec-single-gpu/blob/bccd7ef70291c5b4b0c30b6222bc491039b4cd18/src/minionerec/training/sft_training.py)。

## 5. GRPO 的具体过程与容易踩的坑

从 Q2 最佳 SFT 检查点初始化可训练策略模型与无梯度参考模型；生成旧策略轨迹并记录对应概率。按参考实现控制 KL、裁剪更新；固定参考与定期参考同步是不同设置，必须写入配置。第一版参考每512步同步、mixup alpha0.6，与单卡记录一致。

一条训练输入给出用户历史。受完整 SID 前缀树约束，生成一组 G 个不同商品，每个候选是一条商品 SID 序列。计算训练目标对应的奖励，再用组内均值和标准差形成相对优势：好的候选提高概率，差的降低概率；加入参考策略约束。对这一组候选的优化不等于直接生成一条有多个商品的列表。

主奖励复用核对过的单卡实现：精确命中奖励加排名惩罚。命中候选获得精确奖励1；命中组中，排在前面的错误候选受到更大的归一化惩罚。代码对“整组无命中”返回全部零奖励，具体逻辑见 [奖励实现](https://github.com/wbn11/minionerec-single-gpu/blob/bccd7ef70291c5b4b0c30b6222bc491039b4cd18/src/minionerec/rewards/ranking_grpo.py)。不能以为给排名奖励后所有无命中组都能学到东西。

因此必须记录：整组命中率、零优势组比例、组内奖励标准差、SID合法率、候选唯一率、KL、梯度和验证HR/NDCG。G=4只用于排查工程；正式先试G=16，再基于实测考虑G=8或更大搜索。

先冻结 SFT，在训练集固定2,000个prompt上做候选/奖励回放，不更新权重。若超过90%的组无推荐优势，作为稀疏信号诊断触发点，先分析再长跑。可单独研究更大候选组、训练内动态采样或混入高命中对齐任务；不要不加说明地把真实目标塞进候选，也不要用验证/测试目标作奖励。

Q3 第一版保留少量商品文本→SID的对齐prompt，记录各任务比例及各自零优势率；Q3-A再移除它们做消融。推荐主任务的奖励与目录文本对齐奖励分别报告，不能用后者的高奖励掩盖推荐停滞。

建议：训练集10,000个推荐prompt起步；BF16、梯度检查点、paged_adamw_32bit，lr1e-5，KL系数0.001；策略和参考模型各加载一次，不同时加载商品编码器。G=16、展开microbatch16、累积8，对应每次更新8个不同prompt、128条候选，而不是128个不同用户。正式配置需先核对 trainer 的组完整性与梯度累积语义。

代码基于受约束 beam 候选的推荐 GRPO，是 MiniOneRec/ReRe 风格的改编；不宣称完全等同于原始独立随机采样 GRPO。奖励与推理必须使用同一商品映射，概率统计与 KL 的掩码/归一化必须检查一致性。

## 6. 验证、过拟合和结果比较

每个模型先检查 loss 有限、梯度有限、可恢复训练、新 token 权重发生更新、合法输出无冲突；这些工程诊断不作为效果结果。

经固定seed抽取5,000个验证用户组成快速验证集，每约500次更新检查一次。前几个快速检查不升就调查，不据此直接改动测试集。连续3次验证无提升可早停，连续训练loss下降但验证指标下降标记为过拟合预警；始终回退验证最佳权重。

按事先规则取快速验证的前2个检查点，在全部86,713验证用户上选最终权重。每个最终实验冻结后再测试一次；测试不驱动学习率、奖励或暂停。极小pilot采用固定1,000验证用户，结果只作工程诊断。

主结果表：HR@10/NDCG@10/HR@20/NDCG@20、合法率、覆盖率、参数量、GPU小时、费用、峰值显存；GRPO补充候选组有效信号统计。保存逐用户结果，使改进的绝对值、相对值和配对区间可复核。

## 7. 后续论文方案怎么排

第一轮只做Q1、Q2、Q3及Q2-C，不做所有改动的笛卡尔积。第二轮优先奖励消融、RL持续对齐和现有EMA编码分支；商品编码器替换与行为对比微调再往后。

商品编码器行为微调需从训练期行为构造对比样本，避免留出行为、热门偏差和假负例；完成后重新训练量化器、生成SID并重新SFT。它属于额外设计，不是MiniOneRec冻结商品编码器的基本流程。

SASRec协同奖励只列为探索。采用校准后的候选排名/层级辅助奖励并做训练内部校准与权重消融，不直接把原始logit当作可靠效果指标。教师奖励上涨不能替代最终独立推荐指标。第三方相关探索见 [单卡项目](https://github.com/wbn11/minionerec-single-gpu)。

## 8. 租用前和租用后的执行顺序

租用前还需完成：四段SID的数据转换、tokenizer/词表扩展、Q1/Q2任务开关、梯度与mask诊断、历史过滤和统一商品评测、GRPO组与奖励日志、断点恢复、独立Linux依赖锁定、数据/代码/模型版本清单。当前方案文档完成，不代表这些适配脚本已实现。

租后按顺序：SSH与磁盘检查→下载固定revision的模型→GPU小样本验证→Q0记录→Q1→Q2→训练内候选奖励回放→Q3/Q2-C→验证选模→最终测试→接口演示。Linux依赖单独安装，不复制Windows虚拟环境。

小样本pilot只用训练集10,000目标、验证1,000用户，先20个训练更新与一次推理/评测/恢复检查，再最多100步观测显存和吞吐。能运行后再决定正式样本规模和预算。

服务器起步：A6000 48GB、CPU12–16核、内存64–96GB、持久化磁盘200–350GB。顺序运行实验，不并发加载多个训练模型；tmux和程序内checkpoint/早停负责断线后的运行。

按之前核对的2.85元/小时，24小时为68.40元，这是预算窗口示例，不是完整实验耗时预测。租用价届时重查。总预算应由pilot实测的训练更新速度、每次验证时间、模型下载和数据存储成本计算；原作者约17小时的Industrial SFT+GRPO不能当作Office耗时承诺。

先实现SID候选生成与商品Top-K接口。真正的多商品列表联合生成、工业OneRec奖励模型/DPO、真实线上A/B属于后续单独路线，不能与这一版MiniOneRec式下一商品SFT/GRPO混为同一任务。
