## Hugging Face 固定版本下载

项目中已准备 `scripts/download_qwen15b.py`，采用 [官方 snapshot_download](https://huggingface.co/docs/huggingface_hub/guides/download) 的 `revision` 与 `local_dir` 参数。

Windows 从项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts\download_qwen15b.py
```

Linux 在独立下载环境安装 `huggingface_hub` 后执行：

```bash
python scripts/download_qwen15b.py --output /mnt/generative-recommendation/models/Qwen2.5-1.5B-Instruct
```

脚本会校验文件齐全、权重大小与 SHA256、模型架构，并写入 `download_manifest.json`。成功后状态为 `complete`；中断或失败不能当作已下载完成。重新运行同命令使用 Hub 的已有下载缓存机制继续处理。

若 Hugging Face 的大文件连接较慢，项目脚本可从 Qwen 的 ModelScope 官方仓库获取大权重，配置和 tokenizer 仍取固定 HF revision，并核对同一个官方权重 SHA256：

```powershell
.\.venv\Scripts\python.exe scripts\download_qwen15b.py --weight-source modelscope
```

该模式支持未完成权重的 Range 续传；ModelScope master 的内容只有通过固定权重哈希校验才被接受。没有下载文件丢失的自动恢复承诺，最终以 manifest 和校验结果为准。

## 国内下载备选

若官方 Hugging Face 下载连接不稳定，可使用 ModelScope 官方 SDK。在独立下载环境操作，避免把新依赖混入现有 CPU 训练环境：

```bash
python -m pip install modelscope
modelscope download --model Qwen/Qwen2.5-1.5B-Instruct --local_dir /mnt/generative-recommendation/models/Qwen2.5-1.5B-Instruct
```

这是 ModelScope 自身仓库的下载命令，不能直接套用 Hugging Face commit 作为其 revision。下载完成后用同一校验脚本核对权重：

```bash
python scripts/download_qwen15b.py --verify-only --output /mnt/generative-recommendation/models/Qwen2.5-1.5B-Instruct
```

如权重与固定 HF 哈希不同，先分析版本差异，不把两份来源混进同一对照。`verify-only` 核对大权重的官方哈希并记录其他文件哈希；其他文件与固定 HF 版本完全一致仍需进一步比对。ModelScope 命令来源：[官方 CLI 文档](https://github.com/modelscope/modelscope/blob/master/docs/source/command.md)。

## 下载后的顺序

整个流程是：商品文本 → 冻结 MiniLM 生成商品向量 → RQ-VAE 生成 SID → 构造用户历史 SID 与下一商品 SID 的样本 → 用 Qwen 做 SFT → 评测 → 再考虑 GRPO。Qwen 在这里负责根据用户历史生成下一件商品的 SID；商品向量仍由前面的 MiniLM 生成。

这次 Qwen2.5-1.5B-Instruct 的角色是推荐生成模型。SFT 更新 Qwen 参数及新增 SID token 的 embedding，商品内容向量和 RQ-VAE/SID 保持冻结。若后续改用 Qwen3-Embedding 生成商品向量，应作为另一组实验重新生成向量、训练 RQ-VAE、构建 SID，并重新训练推荐模型；它不是本次 Instruct 权重的直接替代名称。

下载目录中各类文件的作用：

| 文件 | 作用 |
| --- | --- |
| `model.safetensors` | 模型已经训练好的参数；后续全参数 SFT 从这份参数开始更新 |
| `config.json` | 层数、隐藏维度等模型结构配置；加载时据此构建模型 |
| `tokenizer.json`、`vocab.json`、`merges.txt`、`tokenizer_config.json` | 将输入文本转换为 token ID，并定义对话模板；后续在此基础上新增 SID token |
| `generation_config.json` | 默认生成参数；推荐实验会另行明确解码与约束配置 |
| `LICENSE`、`README.md` | 官方许可与模型说明 |
| `download_manifest.json` | 本项目记录的来源、固定版本、文件大小与哈希校验结果 |

先验证原始 tokenizer 和配置能从本地离线读取。保留原始模型目录作为只读实验起点；新增 SID 词表与推荐微调检查点写入新的实验目录。上 A6000 后再做模型加载、小样本前向/反向和合法 SID 推理检查。

下载模型不等于完成推荐训练；当前模型尚不认识我们的新增 SID。Q1/Q2 独立分支必须从相同原始模型版本与同一份 SID 初始化出发。
