# SASRec 本地训练与推理

本项目保留 `baselines/sasrec/main.py`、`model.py`、`utils.py` 的上游版本，
另用 `scripts/run_sasrec.py` 调用原模型，完成可复现的本地训练与全商品评测。
本运行入口属于个人适配，不声称精确复现上游论文成绩。

## 环境

第一版本地运行使用 Python 3.12.13、PyTorch 2.7.1+cpu、NumPy 2.2.6。
硬件为 Intel Core Ultra 7 155H、32GB 内存，未使用 GPU。
安装到项目自己的 `.venv`，不修改系统 Python 环境：

```powershell
uv venv --python 3.12 .venv
uv pip install --python .venv/Scripts/python.exe -r requirements-cpu-lock.txt
```

如果没有 uv，也可在 Python 3.12 创建的虚拟环境中使用 pip：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-cpu-lock.txt
```

后一条命令要求本机已安装 Python 3.12。CUDA 用户需改用对应 PyTorch 构建，
运行入口支持 `--device cuda`，本次只验证 CPU。

## 先检查，再训练

以下命令从项目根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/verify_dataset.py
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/run_sasrec.py --output outputs/sasrec_smoke_new --smoke-only --smoke-steps 20
```

协议测试检查下一物品目标的移位和截断、负例排除完整训练历史、
已知历史过滤、同分排名，以及未来输入不能改变更早位置的特征。
小规模检查真实执行前向、反向、参数更新，并验证保存后重新加载的输出一致。
小规模检查不提供正式推荐指标。

完整训练的起步配置：

```powershell
.\.venv\Scripts\python.exe -u scripts/run_sasrec.py --output outputs/sasrec_office2018_cpu_new --epochs 20 --maxlen 20 --hidden-units 64 --num-blocks 2 --num-heads 2 --batch-size 256 --eval-batch-size 256 --eval-every 5 --patience 2 --threads 4 --seed 2026
```

输出目录必须为空，重复实验应使用新目录，避免覆盖已有权重和记录。
初次小规模检查使用 maxlen=50；完整起步实验使用 maxlen=20，
因为训练历史平均 5.81 项、P95 为 14 项。1,713 个用户的训练历史超过 20 项。
训练输入是训练部分去掉最后一项后截断，因此实际参与训练的位置数也单独记录。

## 样本和损失

假设完整行为是 `[A,B,C,D,E,F,G]`：

- 训练历史 `[A,B,C,D,E]`，验证目标 F，测试目标 G。
- 训练输入 `[A,B,C,D]`，正例 `[B,C,D,E]`，分别补位和截断。
- 有效位置各采一个负例，均匀随机排除用户完整训练历史；不用未来目标过滤负例。
- 对正例计算标签 1 的 BCE，对负例计算标签 0 的 BCE，两项相加。
- padding 不参与损失；原模型结构、位置 embedding、自注意力和点积评分保持不变。

每个 epoch 使用固定 RNG 打乱用户，每个用户处理一次，最后一个 batch 可以较小。
这与上游多进程 sampler 的遍历和 RNG 消耗不同，因此记录为本项目运行协议。
使用 Adam，lr=0.001，betas=(0.9,0.98)，dropout=0.2，未添加 embedding L2。

## 全商品评测

- 每次评测全部 86,713 个用户，每人一个目标。
- 商品候选为全部 25,898 个处理后商品，不采 100 个负例。
- 验证输入只有训练历史；测试输入是训练历史加验证商品。
- 模型仅编码最近 maxlen 项，但候选过滤排除全部已知历史和 padding ID 0。
- 分数为最后位置特征与商品 embedding 的点积；同分时商品 ID 小的优先。
- 输出 Recall@10、NDCG@10、Recall@20、NDCG@20；单目标下 HR 与 Recall 等价。
- 每 5 轮检查验证集，只按验证 NDCG@10 保存 best.pth。
- 最多训练 20 轮，连续 2 次验证未提升则提前停止；选定最佳权重后评测一次测试集。
- 另以训练交互计数构建 Popularity，用相同候选、历史过滤和同分规则评测测试集。

当前数据仍是用户内 leave-two-out、固定商品目录、全数据 5-core，
不能等同于严格全局时间切分或在线 A/B 测试。

## 产物

`outputs/<run>/` 是本地忽略目录：

| 文件 | 用途 |
|---|---|
| `run.json` | 配置、环境、数据指纹、各轮损失、验证和最终测试指标 |
| `best.pth` | 仅由验证 NDCG@10 选择的模型权重与配置 |
| `last.pth` | 最后一轮权重；恢复功能加入后也保存 Adam 和 RNG 状态 |
| `demo.local.json` | 本地数字用户的示例历史、推荐和测试目标，不入 Git |

完整日志也保存在 `outputs/`。汇总指标和脱敏实验说明可以放在 `experiments/`，
原始行为、用户映射、示例用户记录和权重均不提交普通 Git。

## 中断后的恢复

2026-10-07 首次运行完成 11 轮，第 12 轮途中进程退出。旧版 checkpoint
只保存模型权重，恢复时重新初始化 Adam 和 RNG，不能声称与不中断训练逐步一致。
之后的版本保存完整训练状态，并通过测试验证恢复后的下一步参数更新一致。

降低 CPU 占用的恢复命令：

```powershell
.\.venv\Scripts\python.exe -u scripts/run_sasrec.py --output outputs/sasrec_office2018_cpu_resumed_20261007 --resume outputs/sasrec_office2018_cpu_20261007/last.pth --epochs 20 --maxlen 20 --batch-size 128 --eval-batch-size 128 --eval-every 5 --patience 2 --threads 2
```

`--epochs 20` 表示总轮数达到 20，从第 11 轮权重恢复后重新训练第 12 轮。
新目录保留之前的验证记录和最佳权重，只用验证 NDCG@10 更新最佳模型。
初始 11 轮 batch=256、4 线程；恢复阶段 batch=128、2 线程，学习率不变。
记录明确标注恢复模式和两段配置，原目录不覆盖。运行时还把进程优先级设为 BelowNormal。
当前完整恢复保证的是同一训练配置下的 epoch 边界；不保存正在训练的 batch 中间进度。

## 继续训练与过拟合暂停

从第 20 轮完整检查点继续，最多新增 20 轮：

```powershell
.\.venv\Scripts\python.exe -u scripts/run_sasrec.py --output outputs/sasrec_office2018_cpu_extend40_20261007 --resume outputs/sasrec_office2018_cpu_resumed_20261007/last.pth --epochs 40 --maxlen 20 --batch-size 128 --eval-batch-size 128 --eval-every 1 --patience 2 --stop-on-overfit --threads 2
```

本段保留 Adam 和随机状态，学习率、batch、模型配置不变；每轮评测全部验证用户。
当验证 NDCG@10 低于此前最佳值，同时训练 loss 低于最佳验证轮次对应的 loss，
记一次过拟合警告；连续两轮警告就暂停。验证刷新最佳值时清零计数。
只降低训练 loss 或验证成绩持平不会触发这个规则，它是一种保守的迹象检测。
停止依据只使用训练和验证数据，选定权重后才评测测试集。

实际在第 25 轮触发连续两轮警告，已暂停；保留第 23 轮最佳权重。
第 24 轮验证 NDCG@10=0.045112，第 25 轮=0.046475，均低于第 23 轮的 0.048828；
训练 loss 从第 23 轮的 0.428847 降到第 25 轮的 0.410972。
因此这是连续低于最佳值，不能描述为每一轮都比上一轮更低。
详情见 [续训报告](../../experiments/sasrec_cpu_extend40_20261007.md)。

`run.json` 记录每轮 `overfit_monitor`，暂停时保留
`training_paused=true`、`stop_reason=overfitting_signal` 和暂停轮数。
运行任务完成最终评测后状态仍为 `completed`，表示记录工作完成，
不表示一定训练到第 40 轮。`best.pth` 是验证最佳，`last.pth` 是暂停前的完整状态。

## 推理示例

使用本地编号用户的训练历史加验证商品：

```powershell
.\.venv\Scripts\python.exe scripts/recommend_sasrec.py --checkpoint outputs/sasrec_office2018_cpu_extend40_20261007/best.pth --user-id 1 --k 10
```

也可以传入处理后的商品整数 ID，按时间从旧到新：

```powershell
.\.venv\Scripts\python.exe scripts/recommend_sasrec.py --checkpoint outputs/sasrec_office2018_cpu_extend40_20261007/best.pth --history 12 35 68 --k 10
```

整数 ID 取自本次数据映射，不是原始 ASIN。示例 ID 仅用于说明调用方式。
程序加载权重，编码历史，全商品打分，过滤已有行为，然后返回商品 ID、ASIN、标题和分数。
分数不是校准后的点击概率。无历史用户需用热门推荐兜底；此脚本未提供 HTTP 服务。

运行记录中的延迟是在内存中加载模型后，单个用户全商品 Top-10 的 30 次测试，
不包含磁盘读取、网络请求、并发排队；只能作为本机推理参考。
