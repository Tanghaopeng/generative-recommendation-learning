# Q0 → 全参数 SFT → GRPO：多角度评测方案

日期：2026-10-10。状态：实验设计与资产核对完成；没有启动服务器或 Qwen 训练。下列新增评测尚未全部接入代码。

## 1. 固定主线

固定 Amazon 2018 Office Products 的同一划分、MiniLM 商品向量、梯度更新码本的 RQ-VAE 和四段唯一 SID。

| 实验 | 初始化与更新 | 目的 |
|---|---|---|
| Q0 | 原始 Qwen2.5-1.5B-Instruct，固定 seed 扩展 SID 词表，不更新参数 | 推荐适配前的初始表现 |
| Q1 | 从保存的同一 Q0 初始化做全参数 SFT；首版仅历史 SID → 下一 SID | 学习推荐后的表现 |
| Q3 | 从验证集选定的 Q1 检查点做 GRPO | 奖励优化的增量 |
| Q1-C | 从与 Q3 相同的 Q1 检查点继续 SFT | 额外训练预算对照 |

沿用已有实验编号，Q2 文本/SID 多任务对齐暂列后续独立分支。此前方案里“Q3 从 Q2 开始”的建议由本轮主线替代，不同时改变编码器、量化器和 SFT 任务配方。

Q0 新增 SID token 的向量未经推荐训练，不应把其结果解释为已对齐商品语义的大模型零样本推荐能力。前缀树保证输出合法，不保证模型理解商品。保存扩词后的 tokenizer、初始化权重与 SHA-256，Q1 从它加载，不能另行随机初始化。

Q1-C 与 Q3 同时记录 GPU 小时、prompt 数、生成 token 数、训练 token 数和更新步数。选择一个预先声明的近似计算预算进行对照，并报告其余差异；相同 epoch 或步数不等于相同计算量。

## 3. 论文支持与适用范围

- [MiniOneRec，2025，§5.1](https://arxiv.org/html/2510.24431v1)：Top-K 主评测采用 HR 和 NDCG；§3.4 另分析候选唯一率；§5.5.3 提醒奖励上涨可能伴随推荐指标下降。
- [OpenOneRec / RecIF-Bench，2025 年底发布、2026 年开放基准，§3](https://arxiv.org/html/2512.24762)：把评测扩展到商品理解、下一商品预测、标签预测、指令推荐和解释等任务，按任务使用 Recall、Pass、AUC 或 LLM judge。不是每个任务都能直接用 Office 行为数据评测。
- [OneRec Technical Report，2025，§4](https://arxiv.org/html/2506.13695)：除了生成损失，还观察偏好代理、量化器重构/利用率/熵、线上体验及系统成本。其私有偏好分数和线上日志不能在 Office 数据上直接复用。
- [LAAC，2025，§3.1.4](https://arxiv.org/html/2507.21274)：除 HR/NDCG，报告商品覆盖和长尾商品覆盖。这里参考评测维度，不照搬其候选采样、数据和奖励设置。
- [RecBole 官方指标文档](https://recbole.io/docs/recbole/recbole.evaluator.metrics.html)：提供 MRR、覆盖、平均流行度、曝光 Gini 等定义参考。

下面是本项目选择的协议，不声称所有论文都使用了全部指标，也不复用其他数据或候选采样条件下的绝对分数。

## 4. 第一版必报指标

| 角度 | 指标 | 解释与约定 |
|---|---|---|
| 命中 | HR/Recall@5、10、20 | 同一用户仅一个留出目标，HR=Recall，只报一套数值 |
| 排位 | NDCG@5、10、20；MRR@20 | NDCG@10 为预先选定的选模指标；MRR 在目标排名 r≤20 时计 1/r，否则为 0 |
| 正负区分 | AUC-S100、GAUC-S100 | 在固定代理负例集合上独立评分；不把有限 beam 外的商品统一设为最低分 |
| 全目录覆盖 | ItemCoverage@20 | 所有评测用户推荐列表去重后的商品数 / 25,898；固定用户集合比较 |
| 长尾 | TailCoverage@20；TailTargetRecall@20 | 前者看长尾是否获得推荐，后者看目标为长尾商品的用户能否被命中；一并报长尾样本量 |
| 内容多样性 | ILD@20 | 每个列表中不同商品的平均余弦距离，使用固定 MiniLM 向量；是内容多样性代理，不代表用户满意度 |
| 生成质量 | 合法率、重复率、足量率、历史商品泄漏率 | 分别记录原始候选与后处理后列表；约束导致的 100% 合法率是工程保证 |
| 分组表现 | 不同历史长度用户、热门/中等/长尾目标的 Recall/NDCG | 分组只用训练行为定义，报告人数，不把稀疏用户称为新用户冷启动 |
| 成本 | 推理延迟 P50/P95、用户/秒、峰值显存、GPU 小时 | 同卡、同 batch、同 beam、同输入长度上限；训练和推理分别统计 |

长尾预定义：按训练交互次数升序排序，次数相同按 item_id 排序，目录中最低 50% 商品作为 tail，定义固定后用于所有阶段。零训练交互商品另列子组，不能把其结果等同于严格时间冷启动。

TailCoverage = 被推荐过的不同长尾商品数 / 长尾商品总数。
TailTargetRecall 的分母是留出目标属于长尾的评测用户数。
ILD 使用最终去重的实际列表计算；不足 2 件时记缺失并报告数量，不用虚构商品补齐。
足量率@K = 最终有至少 K 件合法、唯一、非历史商品的用户比例。排名指标缺失位置按未命中处理，不从评测用户分母中删除失败样本。

重复率 = 1 - 原始可解析候选中唯一商品数 / 原始可解析候选数，空候选另计失败；历史泄漏和无效 SID 分别统计，避免过滤后掩盖问题。

## 5. 第二版诊断

- 新颖性：推荐商品的平均 `-log2(p_train(i))`，概率用训练次数加一平滑；同时报告平均训练流行度。稀有不等于有用。
- 曝光集中度：全目录推荐曝光 Gini（包含零曝光商品）及头部商品曝光份额，防止不同用户总收到同一批商品。
- 用户间个性化：在固定采样的不同用户对上，计算 `1-Jaccard(Top20_u,Top20_v)`；随机推荐也可能很高，必须结合准确性解释。
- 历史依赖：在固定验证子集去掉历史或打乱顺序，比较指标变化；这是推荐上下文利用诊断，不把变化越大当作越好。
- 生成 NLL：只对真实目标的回答 token（含约定 EOS）计算，固定 tokenizer、mask 和原始词表归一化口径；作为训练诊断，不替代商品准确性。
- SID 前缀：可报告前三段前缀命中，但第四段错误仍是商品推荐错误，不能计入完整商品 HR。

仅在增加对应数据与任务后，再评测文本↔SID 对齐、自然语言约束满足、商品解释和跨域迁移。LLM judge 需固定评委版本、rubric、顺序并抽查；不作为当前商品级命中的替代。

## 6. 上游编码器与量化器审计

固定本轮 SID 时，重构误差、原向量/重构向量余弦相似度、各层码字利用率/死码率、分配熵/有效码字数、三段 SID 碰撞率及最大碰撞组只需随资产记录一次，不会因 Qwen SFT/GRPO 自动改变。后续对照 EMA、RQ-KMeans 或新编码器时再重评。

当前梯度码本 SID manifest：三层已用码字为 84/256、256/256、256/256；三段唯一组 20,332，额外重码商品 5,566（比例约 21.49%），最大碰撞组 34；追加第四段后 25,898 件商品全部唯一。额外重码比例不等于“处于碰撞组内的全部商品占比”。

## 7. 公平性、稳定性与结果解释

1. 固定用户内最后一件测试、倒数第二件验证，其余训练；这是已知完整目录的留出实验，不宣称严格全局时间模拟。
2. 推理历史最长 20 件；历史过滤使用全部已知历史；输出完整四段 SID 映射后的商品列表。
3. 生成模型主比较固定 beam=20，K≤20，不混入 100 负样本评测。更大的 beam 作为单独的效果/成本曲线，不能用 beam20 声称 @50。
4. SASRec 全目录精确评分，生成器完整目录约束下有限 beam 近似搜索，报告此差异；对照各自按同口径导出的列表。
5. 快速验证子集用于工程和筛选，完整验证用于最终选模，测试配置冻结后每个最终实验评测一次；测试结果不能反过来选择奖励或训练轮数。
6. 保存逐用户 ID、目标、排名、有序 Top20、生成失败原因和耗时；附数据、模型、代码、tokenizer、SID 指纹。用相同用户的配对 bootstrap 给主要指标差值提供 95% 区间；预算允许补 3 个训练种子。bootstrap 不能代替种子稳定性。
7. GRPO 单独记录组命中率、全零优势组比例、奖励均值/方差、KL、候选唯一率和不同 prompt 数；只用训练目标构造奖励。奖励变高不是推荐变好的充分证据。
8. 多样性、覆盖或新颖性提高，需要与准确性和成本共同解释；随机推荐也可能覆盖很广。不先拼成任意权重的单一总分。

单目标且固定返回 K 件时，Precision@K=HR@K/K；增加它不会增加独立信息。MAP 在单目标下也与 MRR 重合。不为了指标数量重复报同一信息。

用户已确认加入 AUC/GAUC。采用下节固定离线代理负例协议；Office 评论未提供真实曝光负反馈，不应把未交互一律当作用户不喜欢，也不据此声称测得线上点击能力。CTR、CVR、停留、留存等需要真实日志和线上实验，目前不报告。

### AUC / GAUC 的实现口径

入口：`scripts/evaluate_qwen_auc.py`；纯指标与采样函数：`scripts/recommendation_auc.py`。

- 每人 1 个留出正例、100 个均匀无放回采样的代理负例。验证只排除训练历史和验证目标；测试排除训练+验证历史和测试目标，不读取更晚的记录来过滤候选。保持现有留出数据不变。
- 采样由 seed、split、user_id 决定，与模型和遍历顺序无关。保存逐用户 item_ids、labels、scores 及候选集合 SHA-256，Q0/SFT/GRPO 使用相同用户集合和候选指纹。
- Qwen 分数为固定 prompt 下完整四个 SID token 的 log-probability 之和；使用未屏蔽的完整词表归一化，不含 EOS，不加 beam 分数，不做用户内 min-max 或重新标定。逐候选 teacher forcing；不是只给生成出来的 Top20 评分。
- AUC：全部用户候选一起计算 pooled AUC，衡量跨用户正负例的区分。GAUC：先算每用户 AUC，再按该用户候选数加权；在每人 101 候选条件下等于用户 AUC 的均值。相同分数按 0.5 胜率处理。
- GAUC 更直接反映用户内排序；pooled AUC 会受到不同用户整体分数偏移影响。SID 生成概率不是点击概率，两个指标都不代表曝光日志上的 CTR AUC。
- 默认固定 1,000 用户为诊断子集，可用 `--users 0` 对所有用户评测；子集报告明确标记 diagnostic_only，不能与全量 AUC 混用。S100 不是全目录 AUC，也不能与其他负例数量/采样分布混比。
- 测试须提供已冻结的验证选模记录；AUC 不替代 NDCG@10 选模。脚本需要 CUDA BF16 和已保存的扩词 tokenizer/模型，支持当前单文件 Qwen 检查点；Q0 仍须先完成固定扩词初始化导出。
- 指标单元测试涵盖完美/反向排序、平分、多正例、AUC 与 GAUC 的差别、权重、固定采样和 causal token 对齐。GPU 实际评分未执行，不填造指标。

示例（先在同一固定验证子集比较）：

```bash
python scripts/evaluate_qwen_auc.py --checkpoint outputs/qwen_q1_full/selected --data data/processed/office2018/qwen_sft_adam --split valid --users 1000 --negatives 100 --seed 2026 --candidate-batch-size 4 --output outputs/qwen_q1_full/auc_valid_s100_u1000
```
