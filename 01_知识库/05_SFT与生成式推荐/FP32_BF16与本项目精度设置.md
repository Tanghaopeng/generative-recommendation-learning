# FP32、BF16与本项目精度设置

不是全部模型都用BF16。参数精度、前向算子精度、梯度精度、优化器状态精度要分别看。

| 阶段 | 本项目实际实现 |
|---|---|
| MiniLM商品向量 | 冻结FP32模型，在CPU推理；输出384维float32向量 |
| SASRec | CPU FP32参数、梯度与Adam训练 |
| RQ-VAE梯度码本 | CPU FP32；Adam更新编码器、解码器和码本 |
| RQ-VAE EMA码本 | CPU FP32；Adam更新编码器/解码器；码本用EMA |
| 小型TIGER | CPU FP32；两版独立训练 |
| Qwen Q0 | BF16权重初始化和导出；没有优化器更新 |
| Qwen Q1 SFT | 加载BF16权重、Trainer bf16=True、AdamW；不是所有算子都强制BF16 |

本地Qwen SFT没有显式FP32主权重。普通torch AdamW的moment状态默认随参数dtype创建；本次训练没有逐张量导出服务器优化器dtype，因此这是基于代码实现的判断。BF16计算普遍使用，但不能把“使用BF16”与“精度安排必然充分”混为一谈。

BF16与FP32有近似的指数范围，但BF16有效精度更低。很小的参数更新直接写回BF16可能被舍入；高精度主权重可以累计这些变化。使用FP32优化器状态和使用FP32主权重是两件事。后续低学习率微调应记录各层实际参数delta，而不只看非零梯度。

常见可靠安排是保留FP32主参数/优化器状态，适合的矩阵计算使用BF16 autocast；具体框架可能选择不同方案，显存与吞吐需实测。[PyTorch AMP说明](https://docs.pytorch.org/docs/stable/notes/amp_examples.html)。不能为了精度说明而追改已完成SFT的历史配置和结果。

后续实现原则：优先固定已有第三方参考版本并复用其训练、采样和损失设计，只改本项目数据与四段SID所需部分。额外改变优化器、精度或概率口径时单独记录，不把适配版称为原样复现。固定参考来源见[MiniOneRec参考目录](../../baselines/minionerec_reference/README.md)。
